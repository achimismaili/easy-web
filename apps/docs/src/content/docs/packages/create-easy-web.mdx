## Status

**Reserved.** `@easy-web/create` is published as a placeholder so the name stays with this project. It contains no source: no `src/`, no `bin` and no exports. Do not add it as a dependency. Running `pnpm create @easy-web` does not generate a site today.

## What to use instead

[`@easy-web/cli`](../../getting-started/create-new-site/) is the tool that generates a site. It is config-driven and create-only:

```bash
easy-web create --config ./create.json
```

| | `@easy-web/cli` | `@easy-web/create` |
| :--- | :--- | :--- |
| Status | Published, Phase 1 | Reserved name |
| Ships code | Yes | No |
| Input | A JSON config file | None |
| Node.js | 24 or later (`engines.node` is `>=24`) | not applicable |
| Version | Its own, outside the fixed `@easy-web/*` group | Shares the fixed group version |

The CLI generates a site once. It does not update, deploy or manage one afterwards. See [Create a New Site](../../getting-started/create-new-site/) for the config format and the options.

## Why the Node.js requirement differs

Node.js is a build-time requirement for easy-web sites, and the supported floor for the packages that go into a site is Node.js 22 with Astro 6. The CLI is not one of those packages: it only runs on the machine that generates a site, so it can require Node.js 24 without raising the floor for any site. The compatibility lane asserts that the CLI is not installed in its isolated consumer. See the [Technology Map](../../architecture/technology-map/).
