`@easy-web/core` is the base of the `@easy-web/*` family. One install gives a working site: design tokens, theme helpers, i18n routing and formatting, the SEO integration, the markdown image plugin, every page component, and the content contracts those components accept.

Everything else is an add-on: [`@easy-web/cms-adapters`](../cms-adapters/) for Decap CMS and typed content definitions, `@easy-web/swa` for Azure Static Web Apps, [`@easy-web/auth`](../auth/) for MSAL sign-in, and `@easy-web/brand` for favicons. `@easy-web/cli` generates a new site from a config file.

:::note[Published]
`@easy-web/core` is published on npm. Install it with `pnpm add @easy-web/core`. The five compatibility packages (`theme-core`, `i18n`, `content-blocks`, `seo`, `markdown`) re-export from it and stay through 1.x. See [Migrating to core](../../guides/migrating-to-core/).
:::

## Installation

```bash
pnpm add @easy-web/core
```

`astro` (6 or 7) is the only peer dependency. Start new sites on Node.js 24 with Astro 7; the packed consumer lane also builds core on Node.js 22 with Astro 6. See the [Technology Map](../../architecture/technology-map/).

## Localized URLs and crawl policy

`easyWebSeo()` composes the sitemap integration and injects `robots.txt`; a site's
layout renders `SeoHead` for the document metadata. Do not register a second
sitemap integration or keep a competing `public/robots.txt`. The latter can shadow
the generated route.

### Declare translated routes once

The helpers assume an unprefixed default locale and prefixed additional locales.
For same-slug routes such as `/guide/` and `/en/guide/`, head helpers derive
alternates by replacing the locale prefix, and the sitemap pairs built routes
with the same remaining slug. Neither mechanism translates a slug or creates pages.

For translated slugs, declare one shared `localizedPaths` array and pass it to
both `createI18n()` and `easyWebSeo()`. Otherwise the head helper can invent an
unbuilt URL such as `/en/hilfe/`, while the sitemap fails to pair `/hilfe/` with
`/en/help/`. Leave same-slug pairs out of this array; use `[]` when no translated
slugs need mapping.

This example assumes a site served at the origin root (`base: '/'`), with both
`/hilfe/` and `/en/help/` implemented by the site's pages:

```ts
// src/lib/localization.ts
import { createI18n, type LocalizedPathGroup } from '@easy-web/core/i18n';

export const locales = ['de', 'en'] as const;
export const defaultLocale = 'de';
export const site = 'https://example.invalid';
export const trailingSlash = 'always';
export const localizedPaths: readonly LocalizedPathGroup[] = [
  { de: '/hilfe/', en: '/en/help/' },
];

export const i18n = createI18n({
  locales, defaultLocale, baseUrl: site, trailingSlash, localizedPaths,
});
```

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config';
import easyWebSeo from '@easy-web/core/seo';
import {
  locales, defaultLocale, site, trailingSlash, localizedPaths,
} from './src/lib/localization';

export default defineConfig({
  site,
  base: '/',
  trailingSlash,
  i18n: {
    locales: [...locales],
    defaultLocale,
    routing: { prefixDefaultLocale: false },
  },
  integrations: [
    easyWebSeo({
      localizedPaths,
      sitemapLocales: { de: 'de', en: 'en' },
    }),
  ],
});
```

```astro
---
// In the site's shared layout:
import SeoHead from '@easy-web/core/components/SeoHead';
import { i18n } from '../lib/localization';

const pathname = Astro.url.pathname;
const locale = i18n.getLocaleFromPath(pathname);
---
<head>
  <SeoHead
    title="Example page"
    siteName="Example Site"
    pathname={pathname}
    locale={locale}
    alternates={i18n.getAlternateLinks(pathname)}
  />
</head>
```

`SeoHead` emits the canonical from the current pathname and Astro's `site`; do not
add a second canonical. On `/en/help/`, it is
`https://example.invalid/en/help/`. Both pages' head alternates contain the same
`de` and `en` URLs, including a self-reference, plus `x-default` pointing to
`https://example.invalid/hilfe/`. Both sitemap entries carry the reciprocal `de`
and `en` pair; declared sitemap groups do not add `x-default`.
`localizedHref()` only changes locale prefixes; it does not consult
`localizedPaths`. Use the declared alternates for a translated-slug language switch.

Each group must contain every configured locale, with no unknown locale keys.
Values must begin with a single `/`, contain no query or fragment, and claim
distinct paths across and within groups. With sitemap generation enabled, the
build also rejects declared URLs missing from the sitemap (including filtered-out
routes) and conflicting automatic pairings. A group is not a declaration of
partial translations or proof that the host serves a route.

### Match the configured served URL form

Explicit Astro `trailingSlash: 'always'` or `'never'` wins. When it is `'ignore'`,
the integration resolves directory output to `'always'` and file output to
`'never'`; preserve output warns and assumes `'always'`. `SeoHead` inherits that
resolution, and `createI18n()` reads it when the bundle is created unless given an
explicit `trailingSlash`. Sharing the explicit setting, as above, also avoids
depending on when the bundle is initialized.

`toServedPath()` normalizes leading/trailing slashes and strips queries/fragments;
group lookup ignores trailing slashes, queries and fragments. Neither lowercases
paths nor discovers host redirects. Use the actual path casing and pass a pathname,
not a full URL, to `SeoHead`. Keep `site` and the helpers' `baseUrl` aligned with
the chosen public host; there is no automatic apex/`www` rewrite.

`sitemapLocales` maps every Astro locale ID to the intended BCP-47 language tag.
If the whole option is omitted, the integration warns and uses the IDs themselves
(`de`, `en` here), never guesses `en-EN` or a country. It does not fill missing
entries in a supplied map. Head helpers also use locale IDs as `hreflang`; a
region-specific sitemap map such as `{ en: 'en-GB' }` does not relabel head
alternates automatically. Align those tags deliberately if regional targeting
is needed.

### Keep crawl exclusions consistent

Public mode excludes `/admin`, `/admin/` and descendants from the sitemap and
writes `Disallow: /admin/` in `robots.txt`. An optional
`easyWebSeo({ filter: (url) => ... })` can exclude more sitemap URLs, but cannot
re-admit a built-in exclusion. It does not add robots rules or page metadata.

`easyWebSeo({ noIndex: true })` registers no sitemap and generates
`Disallow: /` without a `Sitemap:` line. `SeoHead` inherits `noindex, nofollow`
unless its `noIndex` prop explicitly overrides the policy (not-found routes
remain noindexed). Conversely, a page-level `noIndex` prop does not remove that
page from the sitemap; coordinate any additional exclusions in the site config.
The opt-in [build-information routes](#public-build-information) have their own
sitemap exclusions.

Review the built HTML, sitemap and `robots.txt` together: the canonical,
self-referencing head alternate and sitemap URL should agree byte-for-byte, and
translated pairs should be reciprocal and point at built pages. This checks
content/configuration, not live redirects, response headers or access control.
Hosting behavior needs separate verification on the chosen platform; this guide
neither configures deployment nor applies Azure Static Web Apps behavior to
GitHub Pages. Crawler directives do not protect private content.

## Public build information

`easyWebSeo()` can opt a site into two prerendered diagnostic routes generated from one closed manifest:

- `/version` is a human-readable page built from core components and tokens.
- `/version.json` is the same information as deterministic JSON for monitoring and support tooling, but it is disabled by default.

```ts
import easyWebSeo from '@easy-web/core/seo';

easyWebSeo({
  buildInfo: {
    site: 'Example Site',
    packages: ['cms-adapters', 'swa'],
    releaseId: 'public-release-label',
    json: true,
  },
});
```

The package reads the exact installed core version and verifies every named add-on is installed at that same fixed-family version. `core` is always included. The only add-ons accepted in this public contract are `auth`, `cms-adapters` and `swa`; individual UI components do not have separate versions.

Both routes are public. They are omitted from the sitemap, and the HTML route carries `noindex`. The JSON route emits `X-Robots-Tag: noindex, nofollow` and `Cache-Control: no-store`, but only hosts with path-specific response-header control can preserve that contract. Therefore JSON generation is an explicit `json: true` opt-in; leave it disabled on GitHub Pages and other plain static-file hosts. `robots.txt` does not block these paths because a crawler must fetch a route before it can observe `noindex`. This is search-index control, not authentication.

The manifest deliberately excludes Node.js, Astro, React, dependency lists, source-control details, CI links, cloud identifiers, environment variables and arbitrary metadata. Static hosts that do not preserve prerendered response headers need an equivalent host-level `X-Robots-Tag` rule for `/version.json`.

### Should a public site expose its version?

Use a public version surface only when it solves an operational need such as confirming a rollout, correlating a support report, or detecting a stale static client. The recommended pattern is a narrow product or package-family release identity, not a software inventory.

Common implementations include:

- a small `/version` or `/version.json` response with an application release identifier;
- a response header containing the same opaque release label;
- an observability release tag kept in monitoring tooling;
- a minimal `/health` response for an application that has a runtime service. A purely static site usually does not need health or readiness diagnostics.

Mature projects use these identifiers for deployment traceability while keeping dependency inventories and infrastructure details in SBOMs, release attestations or restricted operator systems. For example, [Safe publishes a static version manifest](https://github.com/safe-global/safe-wallet-monorepo/pull/7918), while [Mako uses a build identifier to detect stale clients](https://github.com/mako-ai/mako/pull/491).

OWASP treats detailed framework and server versions as useful fingerprinting data. Its [Web Security Testing Guide](https://owasp.org/www-project-web-security-testing-guide/stable/4-Web_Application_Security_Testing/01-Information_Gathering/02-Fingerprint_Web_Server) recommends limiting that detail while keeping systems patched. Hiding versions is not a substitute for updates, and `noindex` is not privacy or access control.

Therefore easy-web exposes one exact fixed-family version and intentionally enabled easy-web capabilities only. It does not publish framework versions, the dependency tree, per-component versions, infrastructure identifiers or source-control metadata.

### Cards

**`Card`** takes an `item` contract. It links when `item.href` is set, and the alt text comes only from `item.image.alt`.

| Prop | Type | Required |
| :--- | :--- | :--- |
| `item` | `Item & Partial<Linkable>` | yes |

Use `<Card item={gallery} headingLevel="h2" />` for cards directly below the page's

with legacy props and changes semantics only, not title styling.

Local assets retain their intrinsic HTML `width` and `height` attributes; the card's scoped CSS controls the displayed proportions without requiring a global image reset.

**`CardGrid`**: responsive grid wrapper, `class`.

### SEO and errors

| Component | Props |
| :--- | :--- |
| `SeoHead` | `title`, `pathname`, `locale`, `siteName` (required); `description`, `ogType`, `ogImage`, `themeColor`, `manifest`, `noIndex`, `twitterCard`, `twitterSite`, `alternates`, `trailingSlash`, `structuredData` |

`SeoHead` derives `og:locale:alternate` only from `alternates` (the existing
`{ hreflang, href }[]` links). Empty or omitted alternates emit no OG alternate.
`x-default`, the normalized current locale and duplicate locales are excluded from
OG metadata without changing the hreflang links. Language/region tags normalize to
OG underscores and casing (for example `en-GB` to `en_GB`); bare `de` and `en`
retain their historical `de_DE` and `en_US` mappings.

#### Not-found page ownership

`NotFound` is a host-independent body component, not a route generator or an HTTP
status handler. Keep each site's 404 page a thin shell: the site owns the route,
layout, document language, SEO metadata and content loading; the component owns
the shared body and token-based styling. Keep that shell public rather than
wrapping it in a sign-in requirement.

```astro
---
// src/pages/404.astro; Base is the site's own layout.
```

For localized pages, pass the matching content slice and locale props. The
default home link is `/` for the default locale and `/<currentLang>/` otherwise;
set `rootHref` explicitly when the site's base path or locale routing differs.
Supply `alternateHref` only when the target page exists.

Site-owned, CMS-editable copy can use `NotFoundContent` from
`@easy-web/core/contracts` or `notFoundSchema` from
`@easy-web/core/schemas/notFound`. The schema is an open locale-keyed record of
optional `image` (string), `heading` and `message` fields; it does not register a
collection or CMS form, generate translations or enforce locale completeness.
Register content and editing fields in the site. With Astro's glob loader's
default ID generation, `notFound.json` at the collection root gets entry ID
`notfound`, not `notFound`; use the actual collection name and loader ID when
calling `getEntry`.

#### Validate artifacts separately from hosting

After a site build, use its existing test runner to check the **actual emitted
files**, not a fixed path list copied from another site:

- Confirm the root 404 artifact and every deliberately authored localized 404
  route exist. With the workspace's Astro 7 directory output, the root special
  route is `404.html`; inspect localized output for the site's `build.format`,
  base path and routing configuration instead of assuming every 404 is
  `/<locale>/404/index.html`.
- Inspect each rendered body for the intended heading/message and a home link to
  the correct locale root, including any base path.
- If the site requires translated CMS copy, check every configured locale has a
  non-whitespace `heading` or `message`. Schema acceptance alone is insufficient:
  missing fields use built-in fallback copy, while empty strings do not.

These are build-artifact smoke tests, not proof that a missing URL returns HTTP
404. `astro preview` is not an emulator for a hosting provider's routing config;
do not assume a particular missing-route status or fallback body across versions
and adapters. An operator must separately verify a unique, nonexistent URL on
the deployed target returns HTTP 404 **and** the intended body and home link,
including locale-prefixed URLs where applicable.

For Azure Static Web Apps, use the optional
[`@easy-web/swa` integration and configuration checks](https://github.com/achimismaili/easy-web/blob/main/packages/easy-web-swa/README.md#validation-boundaries).
Other hosts need their own fallback configuration. Installing a package or
following this guidance does not wire site tests or post-deployment checks.
