## Installation

```bash
pnpm add @easy-web/cms-adapters
```

## Overview

`@easy-web/cms-adapters` is the CMS add-on to [`@easy-web/core`](../core/). It integrates [Decap CMS](https://decapcms.org/) and gives you:

1. **Typed content definitions.** `field.*` builders, `fieldSets.*` and `defineContentType` / `defineSingleton` describe a content type once, in Decap's own field format.
2. **Generators.** `toAstroSchema` turns a definition into the zod schema for `src/content.config.ts`; `buildDecapConfig` turns all definitions into the Decap config. `InferData` gives the TypeScript type.
3. **`AdminPage`.** A standalone `/admin` page that loads Decap from a CDN and takes the generated config directly, so there's no hand-written `config.yml`.
4. **Source-asset previews.** The opt-in `easyWebCmsPreviewAssets()` integration makes explicit `src/assets` mappings available to Decap without changing frontend image optimization.

Because the form, the schema and the type come from one definition, they can't drift apart. Pair each definition with an `assertImplements` check against the [core contracts](../core/#content-contracts) and drift fails the build. [Writing content types](../../guides/content-types/) is the step-by-step guide.

See [ADR 0006](https://github.com/achimismaili/websites/blob/main/docs/decisions/0006-cms-agnostic-adapter-pattern.md) for the adapter-pattern design rationale.

## Content definitions

```ts
// src/content/model.ts
import { defineContentType, defineSingleton, field, fieldSets, type InferData } from '@easy-web/cms-adapters';
import { assertImplements, type Article } from '@easy-web/core/contracts';

export const news = defineContentType({
  name: 'news',
  label: 'Neuigkeiten',
  folder: 'src/content/news',
  publish: 'missing-date-means-draft',
  mediaFolder: 'src/assets/news',
  publicFolder: '/src/assets/news',
  fields: [...fieldSets.article(), field.body()],
});

export const navigation = defineSingleton({
  name: 'navigation',
  label: 'Navigation',
  file: 'src/content/siteConfig/navigation.json',
  fields: fieldSets.navigation(['de', 'en']),
});

export const contentTypes = [news] as const;
export const singletons = [navigation] as const;

assertImplements<InferData<typeof news>, Article>();
```

### `defineContentType(options)`

| Option | Type | Required | Notes |
| :--- | :--- | :--- | :--- |
| `name` | `string` | yes | Decap collection name |
| `label` | `string` | yes | |
| `labelSingular` | `string` | no | |
| `folder` | `string` | yes | Entry folder |
| `fields` | `FieldDef[]` | yes | `field.*` calls and spread `fieldSets.*` |
| `format` | `'md' \| 'yml' \| 'json'` | no | |
| `slug` | `string` | no | Decap slug template |
| `identifierField` | `string` | no | Defaults to `title`, then `name` |
| `create`, `delete` | `boolean` | no | |
| `sortableFields` | `string[]` | no | |
| `locales` | `string[]` | no | Two or more: one collection per locale plus `locale` and `translationKey` fields |
| `publish` | `PublishRule` | no | Adds an optional `publishDate` field |
| `variants` | `{ discriminator, label, options }` | no | One Decap form per variant, one schema as a discriminated union |
| `mediaFolder`, `publicFolder` | `string` | no | Image locations; a `/src/` public folder makes images Astro assets |

### `defineSingleton(options)`

For a single data file such as navigation or site settings: `name`, `label`, `file`, `fields`, and optional `mediaFolder` / `publicFolder`.

### Field builders and field sets

`field` has one builder per Decap widget: `string`, `text`, `body`, `number`, `boolean`, `color`, `date`, `select`, `hidden`, `image`, `images`, `list`, `object`, `navItems`, `perLocale`. `fieldSets` has `item`, `page`, `article`, `event`, `organization`, `person`, `product`, `siteSettings`, `navigation`, `notFound` and `galleryVariants`, each matching the core contract of the same name. Both are documented in [Writing content types](../../guides/content-types/#field-builders).

### Generators

| Export | Returns |
| :--- | :--- |
| `toAstroSchema(definition)` | zod schema for `defineCollection({ schema })` |
| `InferData<typeof definition>` | TypeScript data type (body excluded) |
| `buildDecapConfig(options)` | Complete Decap config object |
| `toDecapCollections(definition)` | Decap folder collections for one definition |
| `toDecapFiles(singletons)` | Decap files collection for singletons |

```ts
// src/content.config.ts
import { defineCollection } from 'astro:content';
import { glob } from 'astro/loaders';
import { toAstroSchema } from '@easy-web/cms-adapters';
import { news } from './content/model';

export const collections = {
  news: defineCollection({
    loader: glob({ pattern: '**/*.md', base: './src/content/news' }),
    schema: toAstroSchema(news),
  }),
};
```

`buildDecapConfig` options:

| Option | Type | Required |
| :--- | :--- | :--- |
| `backend` | `{ name: 'azure'; repo; tenant_id; app_id; branch? }` | yes |
| `mediaFolder` | `string` | yes |
| `publicFolder` | `string` | yes |
| `contentTypes` | `ContentTypeDef[]` | yes |
| `singletons` | `SingletonDef[]` | no |
| `singletonsLabel` | `string` | no |
| `locale` | `string` (editor UI, default `de`) | no |
| `publishMode` | `string` | no |

## Admin page from definitions

`AdminPage` is a standalone Astro component that renders a complete HTML document. It deliberately avoids the site layout, so place it at a route with no shared layout (typically `/admin`).

**Import:** `import AdminPage from '@easy-web/cms-adapters/components/AdminPage.astro'`

```astro
---
// src/pages/admin.astro
import { buildDecapConfig } from '@easy-web/cms-adapters';
import AdminPage from '@easy-web/cms-adapters/components/AdminPage.astro';
import { contentTypes, singletons } from '../content/model';

const config = buildDecapConfig({
  backend: {
    name: 'azure',
    repo: import.meta.env.CMS_REPO,
    tenant_id: import.meta.env.CMS_TENANT_ID,
    app_id: import.meta.env.CMS_APP_ID,
  },
  mediaFolder: 'src/assets',
  publicFolder: '/src/assets',
  contentTypes,
  singletons,
});
---
<AdminPage config={config} lang="de" title="Inhalte" />
```

| Prop | Type | Default |
| :--- | :--- | :--- |
| `config` | `object` | none; without it Decap loads `/admin/config.yml` (legacy) |
| `decapVersion` | `string` | `3.14.0`; only honoured together with `config` |
| `lang` | `string` | `en` |
| `title` | `string` | `Content Manager` |

Keep tenant and app ids out of the repo: read them from the environment as above.

## CMS previews for `src/assets`

Astro does not serve `src/assets` at literal browser paths. `toAstroSchema()` intentionally turns a `/src/` image into `ImageMetadata`, so normal pages render optimized `/_astro/...` URLs. Decap uses `public_folder` literally and needs the same path to resolve in its editor.

```ts
// astro.config.mjs
import { defineConfig } from 'astro/config';
import { easyWebCmsPreviewAssets } from '@easy-web/cms-adapters';

export default defineConfig({
  integrations: [easyWebCmsPreviewAssets({
    folders: [
      { source: 'src/assets/galleries', publicPath: '/src/assets/galleries' },
      { source: 'src/assets/images', publicPath: '/src/assets/images' },
    ],
  })],
});
```

That two-folder example matches Party200. Harley uses one mapping for `src/assets/images`. The pilot's `public/images` setup is already browser-addressable and does not need this integration. Mappings are always explicit; source and public suffixes must correspond one-to-one, while duplicate or overlapping public prefixes are rejected.

In development, valid owned browser-image paths serve the contained original with `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`. In production, raster images (`jpg`, `jpeg`, `png`, `webp`, `avif`) are auto-oriented and fitted inside 1600x1600 without enlargement. JPEG/WebP use quality 80, AVIF quality 50, and PNG uses lossless compression. SVG/GIF pass through only within the limits. Inputs over 25 MiB, emitted files over 5 MiB, MOV/video, unknown or malformed files, symlink escapes, and output collisions are never published. Warnings are summarized rather than logged per successful file.

Add `sharp@^0.35.0` to the site when enabling the integration. It is an optional peer loaded lazily. Frontend rendering remains Astro-optimized at `/_astro/...`; the emitted files exist only for Decap's literal preview requests.

### AdminPage with `config.yml`

```astro
---
// src/pages/admin.astro
// No layout: AdminPage renders the full HTML document itself
import AdminPage from '@easy-web/cms-adapters/components/AdminPage.astro';
---
<AdminPage />
```

Without `config`, the component loads Decap CMS from `unpkg.com/decap-cms@3.14.0` and expects `public/admin/config.yml` to be present.

## Config generator (deprecated)

### `generateDecapConfigString`

Generates a Decap CMS `config.yml` string for the Azure DevOps backend, pre-configured for blog and pages collections with per-locale support.

**Signature:**
```typescript
function generateDecapConfigString(options: DecapConfigOptions): string
```

```typescript
interface DecapConfigOptions {
  tenantId: string;   // Entra tenant ID
  appId: string;      // Entra app registration client ID for the CMS
  adoOrg: string;     // Azure DevOps organisation slug
  adoProject: string; // Azure DevOps project name
  adoRepo: string;    // Repository name
  branch?: string;    // Target branch (default: 'main')
  locales?: string[]; // Locales to create blog collections for (default: ['de', 'en'])
}
```

```typescript
import { generateDecapConfigString } from '@easy-web/cms-adapters';

const yaml = generateDecapConfigString({
  tenantId: process.env.ENTRA_TENANT_ID,
  appId: process.env.ENTRA_CMS_APP_ID,
  adoOrg: 'my-org',
  adoProject: 'my-project',
  adoRepo: 'my-repo',
  branch: 'main',
  locales: ['de', 'en'],
});

console.log(yaml); // Full config.yml content ready to write to public/admin/config.yml
```

### `generateDecapConfig`

Async variant of `generateDecapConfigString` that also **writes** the generated config to a file path. Returns a result object indicating success or failure. Will not overwrite an existing file.

**Signature:**
```typescript
async function generateDecapConfig(options: DecapConfigWriteOptions): Promise<DecapConfigWriteResult>
```

```typescript
interface DecapConfigWriteOptions extends DecapConfigOptions {
  outputPath: string; // Absolute or relative path to write config.yml
}

interface DecapConfigWriteResult {
  success: boolean;
  content: string;  // The generated YAML string
  error?: string;   // Present only when success === false
}
```

```typescript
import { generateDecapConfig } from '@easy-web/cms-adapters';
import path from 'node:path';

const result = await generateDecapConfig({
  tenantId: process.env.ENTRA_TENANT_ID!,
  appId: process.env.ENTRA_CMS_APP_ID!,
  adoOrg: 'my-org',
  adoProject: 'my-project',
  adoRepo: 'my-repo',
  outputPath: path.join(process.cwd(), 'public', 'admin', 'config.yml'),
});

if (!result.success) {
  console.error(result.error);
} else {
  console.log('config.yml written successfully');
}
```

### `DecapConfigOptions`

```typescript
interface DecapConfigOptions {
  tenantId: string;
  appId: string;
  adoOrg: string;
  adoProject: string;
  adoRepo: string;
  branch?: string;    // default: 'main'
  locales?: string[]; // default: ['de', 'en']
}
```

### `DecapConfigWriteOptions`

Extends `DecapConfigOptions` with `outputPath: string`.

## Frontmatter types (deprecated)

Use `InferData<typeof definition>` instead. These hand-written types match the Decap CMS collection schemas generated by `generateDecapConfigString`. Import them in your Astro content collection config for type-safe frontmatter.

```typescript
import type {
  BlogFrontmatter,
  PageFrontmatter,
  SiteConfig,
} from '@easy-web/cms-adapters';
```

### `BlogFrontmatter`

Frontmatter shape for entries in `src/content/blog/[locale]/`.

```typescript
// Fields include: title, description, pubDate, draft, locale, translationKey, heroImage?
import type { BlogFrontmatter } from '@easy-web/cms-adapters';
```

### `PageFrontmatter`

Frontmatter shape for entries in `src/content/pages/`.

```typescript
// Fields include: title, description, locale, translationKey
import type { PageFrontmatter } from '@easy-web/cms-adapters';
```

### `SiteConfig`

Type for site-wide configuration data managed in Decap (e.g. `src/content/data/company.json`).

```typescript
// Fields include: companyName, defaultTitle, url
import type { SiteConfig } from '@easy-web/cms-adapters';
```

### Additional types

The package also exports: `EventFrontmatter`, `PersonFrontmatter`, `LinkItem`, and `NavigationConfig` — imported from the same entry point.

## Architecture note

Decap CMS uses an OAuth hash-fragment redirect flow. Mounting it inside the site's main Astro layout would allow the hash fragment to collide with MSAL's own redirect handler. The `AdminPage` component isolates Decap to its own page to prevent this.

For Entra ID app registration guidance for the CMS backend, see `docs/entra-cms-setup.md` in your instance repo.
